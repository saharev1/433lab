# Архитектура и план Backend-разработки для Claude

Привет, Claude! Ниже описан план по разработке бэкенда для проекта 433lab, составленный на основе требований пользователя. Твоя задача — спроектировать и реализовать серверную часть, а также интегрировать её со статическим фронтендом.

## Основной функционал

1. **Регистрация и Авторизация:**
   - Роли: `Admin` (администратор) и `User` (пользователь).
   - Возможность регистрации и входа для пользователей.
   - Админ должен иметь защищенный доступ к загрузке контента.

2. **Загрузка и хранение медиа (Admin):**
   - Администратор может загружать фото и видео в существующие разделы сайта ("Слушать", "Смотреть" и т.д.).
   - Все загружаемые файлы должны сохраняться в строго заданную директорию на сервере.
   - Структура каталогов для хранения: 
     - `/media/Photos/`
     - `/media/Videos/`

3. **Взаимодействие пользователей с контентом:**
   - **Лайки**: Пользователи могут ставить лайки на медиафайлы.
   - **Комментарии**: Пользователи могут оставлять комментарии под контентом.
   - **Избранное**: Должен быть реализован раздел "Избранные", в котором отображаются все медиафайлы, которые лайкнул текущий пользователь.

## Технические требования и интеграция

- **Стек технологий**: На твой выбор (например, Node.js + Express/FastAPI + PostgreSQL/MongoDB). Важно, чтобы сервис легко контейнеризировался.
- **Инфраструктура Docker**: Текущий проект развёрнут в Docker (через nginx на порту 6060). Бэкенд нужно будет добавить как отдельный сервис в `docker-compose.yml`, а nginx настроить как reverse-proxy для маршрутизации запросов (например, все `/api/*` отправлять на бэкенд).
- **API (REST)**: 
  - `POST /api/auth/register`, `POST /api/auth/login`
  - `POST /api/media/upload` (только для Admin)
  - `GET /api/media/:section` 
  - `POST /api/media/:id/like`, `POST /api/media/:id/comment`
  - `GET /api/user/favorites`

## Новые задачи (Поиск и сохранение состояния навигации)

### 1. Индексация и Поиск
- **Поиск по тегам постов**: При добавлении медиа/поста через админ-панель должна быть возможность указать тег (теги). Необходимо добавить соответствующее поле в БД (например, в таблицу `Media`).
- При использовании строки поиска (на экране меню) должен производиться поиск по этим тегам (и названиям постов), выдавая соответствующие посты в результатах.
- **Поиск по разделам меню**: Если поисковый запрос совпадает (или содержит) название раздела (например, "Проза", "Слушать", "Смотреть"), поиск должен находить этот раздел, позволяя пользователю быстро перейти в него.
- Реализовать API эндпоинт для поиска (например, `GET /api/search?q=...`) и отображение результатов на фронтенде.

### 2. Сохранение текущего экрана при перезагрузке
- В данный момент при обновлении страницы (перезагрузке) состояние сбрасывается и пользователя перекидывает на главный стартовый экран.
- **Задача**: Сделать так, чтобы при перезагрузке страницы пользователь оставался на том экране/разделе, где он находился. 
- Для реализации можно использовать URL hash (например, `/#screen-listen`) или `sessionStorage`/`localStorage`. Фронтенд (`app.js`) при инициализации должен считывать это состояние и сразу отображать нужный экран, минуя стартовую заставку.

### Статус: выполнено (2026-07-18)

**Поиск:**
- БД: колонка `tags TEXT NOT NULL DEFAULT ''` в таблице `media` + автомиграция `ALTER TABLE` для существующих баз (`backend/db.js`).
- Бэкенд: теги принимаются при загрузке (`POST /api/media/upload`, поле `tags` — через запятую, нормализуются: пробелы/`#` убираются) и редактируются через `PATCH /api/media/:id`; отдаются массивом в поле `tags`. Новый эндпоинт `GET /api/search?q=...` — регистронезависимый поиск по названию, описанию и тегам (фильтрация в JS, т.к. LIKE/lower() SQLite не понимают кириллицу; на объёмах сайта это дёшево).
- Фронтенд: поле «Теги» в форме загрузки и в форме редактирования админа. Enter в любой строке поиска открывает экран `#screen-search`; на нём живой поиск при наборе (debounce 350мс). Результаты: совпавшие названия разделов (клик — переход в раздел) + посты (карточка с плеером/фото, лайком, комментариями, тегами и ссылкой на раздел). Совпадение разделов ищется по словарю SCREEN_NAMES на клиенте.

**Сохранение экрана:**
- `app.js`: текущий экран пишется в URL-хэш через `history.replaceState` (без засорения истории браузера) при каждом переходе и goBack; при загрузке страницы экран из хэша активируется сразу, минуя заставку (фон-дорога скрывается для светлых экранов). Навигация переведена на делегирование событий + добавлен `window.navigateTo(screenId)` для программных переходов.
- `api.js` при загрузке подтягивает контент восстановленного раздела (loadSection/loadFavorites).
- Ограничение: текст поискового запроса после перезагрузки не восстанавливается (экран поиска откроется пустым).

Проверено: смоук-тест бэкенда на :3997 (загрузка с тегами, нормализация, поиск по тегу/названию в разных регистрах, PATCH тегов, пустой запрос), скриншоты headless Chrome — `#screen-listen` и `#screen-search` восстанавливаются из хэша без заставки.
